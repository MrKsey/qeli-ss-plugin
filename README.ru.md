# qeli-ss-plugin

SIP003-плагин для [shadowsocks](https://shadowsocks.org), который несёт **весь**
TCP-трафик `ss-local` ↔ `ss-server` по **одному долгоживущему соединению** —
туннелю [qeli](https://github.com/litvinovtd/qeli) (fake-TLS) с мультиплексированием
потоков:

```text
приложения → ss-local → [клиент плагина] ══ qeli fake-tls туннель ══ [сервер плагина] → ss-server → интернет
                            mux (фреймы stream-id)                     demux
```

Для пассивного наблюдателя (DPI) туннель выглядит как обычный TLS 1.3 к хосту
CDN; под капотом — гибридный постквантовый хендшейк и записи с шифрованием.

**English version: [README.md](README.md).**

## Модель шифрования

Плагин сам шифрует всё, что уходит в провод. Открытыми остаются только два
loopback-плеча (по определению SIP003 они локальные):

```text
приложение ──(открыто, loopback)── ss-local ──(открыто, loopback)── клиент плагина
                                                                        ║
              ══ шифруется отсюда: qeli fake-tls туннель ══            ║
              ║  • fake-TLS хендшейк: X25519 + ML-KEM-768               ║
              ║  • AEAD-записи: ChaCha20-Poly1305 + анти-реплей         ║
              ║  • mux-фреймы едут ВНУТРИ AEAD-записей                  ║
                                                                        ║
                                                        сервер плагина ──(открыто, loopback)── ss-server ──> интернет
```

* **Хендшейк** (`src/handshake.rs`): правдоподобный полёт записей TLS 1.3
  (ClientHello → ServerHello → … → Finished) выполняет гибридный обмен
  ключами **X25519 + ML-KEM-768**; авторизация по паролю происходит уже
  *внутри* зашифрованного канала.
* **Данные** (`src/carrier.rs`): каждый mux-фрейм запечатывается в AEAD-запись
  (ChaCha20-Poly1305, одетая под TLS, скользящее окно анти-реплея) до того,
  как коснётся сокета.
* Собственное AEAD shadowsocks продолжает работать поверх — транзитный
  участок зашифрован дважды: цена неотличимости от TLS.

### Где задаётся SNI

В `plugin_opts`, опция `sni=` (на стороне клиента — SNI живёт в ClientHello,
который отправляет клиент):

```sh
--plugin-opts "password=...;serverkey=...;sni=cdn.example.com"
```

* По умолчанию: `www.cloudflare.com`.
* `sni=` (пусто) — не отправлять расширение SNI вовсе (тоже валидный TLS).
* Значение: ASCII-хост ≤ 253 байт; иначе — ошибка конфигурации.

### «Режим» fake-tls

Переключателя режимов нет — fake-TLS **и есть** wire-профиль этого плагина,
зашитый в хендшейк (qeli `FakeTlsHandshake`). На проводе всегда настоящая
хореография записей TLS 1.3, а после «Finished» AEAD-записи выглядят как
обычные TLS `application_data`. Альтернативного профиля (в стиле
`obfs=http`) не существует — поэтому и опции для него нет.

## На чём построено

Плагин переиспользует ядро [qeli](https://github.com/litvinovtd/qeli) как
библиотеку (крейт `qeli` / либа `qeli_core`):

* **Fake-TLS wire-профиль** — в точности хореография записей
  ClientHello/ServerHello/…/Finished из TLS 1.3 с настраиваемым SNI
  (по умолчанию `www.cloudflare.com`): поток неотличим от обычного HTTPS к CDN.
* **Гибридный постквантовый обмен ключами** — X25519 + ML-KEM-768 (FIPS 203):
  туннель конфиденциален даже против будущего квантового противника,
  ломающего ECDH («harvest now, decrypt later»).
* **AEAD-записи** — ChaCha20-Poly1305 в записях, одетых под TLS, со
  скользящим окном анти-реплея (≈ 2048 пакетов, как у WireGuard).
* **Идентичность сервера, привязанная к транскрипту** — сервер доказывает
  владение долгоживущим статическим ключом, привязанным к хендшейку; клиент
  может закрепить ключ (анти-MITM) или доверять при первом использовании.

## Что добавлено плагином

* **SIP003-обвязка** — переменные окружения `SS_LOCAL_*`/`SS_REMOTE_*`,
  строка `plugin_opts`, роли клиента и сервера.
* **Мультиплексор потоков** (`src/mux.rs`) — фреймы
  `OPEN/DATA/CLOSE/PING/PONG`
  (`type(1) ‖ stream(4) ‖ len(2) ‖ payload`, ≤ 16 КиБ на DATA), по одному на
  AEAD-запись. Одно соединение shadowsocks = один stream id.
* **Долгоживущий носитель** (`src/carrier.rs`) — циклы записи/чтения, реестр
  демультиплексирования, keepalive и per-stream «насос», соединяющий
  локальный сокет с его потоком.
* **Проброс half-close** — FIN от `ss-local` уходит фреймом `CLOSE`, FIN-ит
  upstream, а путь ответа продолжает читать (настоящее полудуплексное
  закрытие, а не разрыв соединения).
* **Авторизация** — единый общий пароль (сравнение за константное время)
  внутри шифрованного канала + опциональный пин ключа сервера. Один пароль
  обслуживает любое число клиентов с любых хостов.

### Устойчивость (каждое поведение покрыто тестами)

* **1–2 испорченные или повторённые записи не убивают туннель.** Плохая запись
  (невалидный AEAD-тег / окно реплея / кривой фрейм) отбрасывается; туннель
  умирает только после 8 *подряд* плохих записей.
* **Мёртвый узел детектится за секунды, а не минуты.** Keepalive PING каждые
  `ping` секунд (по умолчанию 2) с фиксированным грейсом 2 с → худший случай
  детекта ≈ 4 с. Молча зависший сервер убивается, клиент лениво
  перезванивается, трафик продолжается по новому туннелю.
* **Хендшейки ограничены по времени с обеих сторон** — узел, который
  подключился и «завис», не может повесить дозвон или сервер
  (`timeout=`, по умолчанию 10 с).
* **Один застрявший потребитель не замораживает туннель.** Поток, чей
  локальный читатель стоит 5 с, отбрасывается (с отправкой `CLOSE` пиром),
  а не блокирует общий читатель (head-of-line block).
* **Записи ограничены по времени** — зависшая запись в провод убивает туннель
  (10 с); зависшая локальная запись abandons только свой поток (30 с).

### Производительность

* Записи читаются большими кусками и разбираются из буфера на курсоре — без
  аллокаций на каждую запись на пути чтения, без квадратичных drain'ов.
* `TCP_NODELAY` на всех сокетах (туннель + локальные) — мелкие интерактивные
  фреймы не задерживаются Наглом.
* Один фрейм на AEAD-запись: wire-формат идентичен qeli (DPI видит только
  TLS-образные записи обычных размеров); трафик большой ёмкости едет
  фреймами DATA по 16 КиБ.

## Использование

### 1. Сгенерировать идентичность сервера (однократно)

```sh
qeli-ss-plugin --genkey
# private key (key=...):        9f2c...   ← на сервер, держать в секрете
# public  key (serverkey=...):  a41b...   ← на клиент, закрепить
```

### 2. Сторона сервера (с `ss-server`)

`ss-server` слушает на loopback; плагин слушает на публичном интерфейсе и
форвардит демультиплексированные потоки ему:

```sh
ss-server -s 127.0.0.1 -p 1310 -k mypassword -m chacha20-ietf-poly1305 &
SS_LOCAL_HOST=127.0.0.1 SS_LOCAL_PORT=1310 \
SS_REMOTE_HOST=0.0.0.0 SS_REMOTE_PORT=8443 \
qeli-ss-plugin "s=1;key=<hex-приватного-ключа>;password=<пароль-плагина>"
```

### 3. Сторона клиента (с `ss-local`)

```sh
SS_LOCAL_HOST=127.0.0.1 SS_LOCAL_PORT=1080 \
SS_REMOTE_HOST=<сервер> SS_REMOTE_PORT=8443 \
qeli-ss-plugin "password=<пароль-плагина>;serverkey=<hex-публичного-ключа>"
```

```sh
ss-local -s <сервер> -p 8443 -b 127.0.0.1 -l 1080 \
  -k mypassword -m chacha20-ietf-poly1305 \
  --plugin qeli-ss-plugin \
  --plugin-opts "password=<пароль-плагина>;serverkey=<hex-публичного-ключа>"
```

### Справочник `plugin_opts`

| опция | сторона | смысл | по умолчанию |
|---|---|---|---|
| `s=1` / `server=1` | обе | роль сервера (`0` = клиент) | клиент |
| `password=<секрет>` | обе | **обязательный** секрет авторизации; один пароль — любое число клиентов с любых хостов | — |
| `sni=<хост>` | клиент | fake-TLS SNI (пусто = не отправлять) | `www.cloudflare.com` |
| `serverkey=<hex64>` | клиент | пин публичного статического ключа сервера | TOFU |
| `key=<hex64>` | сервер | приватный ключ идентичности (`--genkey`) | эфемерный (в логе) |
| `ping=<сек>` | обе | интервал keepalive; детект ≤ `ping`+2 с | `2` (`0` = выкл) |
| `timeout=<сек>` | обе | таймаут подключения/хендшейка | `10` |

Действует SIP003-экранирование: `\;`, `\=`, `\\` внутри значений.

Готовые конфиги: [`examples/`](examples/) (CLI для shadowsocks-libev и JSON
для shadowsocks-rust, клиент + сервер).

## Standalone-режим (без shadowsocks)

Плагин умеет работать и **напрямую**, по собственному **JSON**-конфигу — без
`ss-local`/`ss-server` и без переменных окружения `SS_*`. Standalone-клиент —
простой TCP-форвардер (каждое принятое соединение = один поток в общем
туннеле); standalone-сервер форвардит демультиплексированные потоки на
**любой** TCP-сервис (HTTP-сервер, sshd, база данных — или ss-server, если он
всё же нужен в середине):

```sh
qeli-ss-plugin --config standalone-server.json   # на сервере
qeli-ss-plugin --config standalone-client.json   # на клиенте
```

Конфиг — JSON; поле `"_comment"` (строка или массив строк) разрешено и
игнорируется (в JSON нет комментариев), неизвестные ключи — **ошибка**
конфигурации (опечатка не должна молча игнорироваться). Standalone-ключи:

| ключ | смысл |
|---|---|
| `role` | `"client"` или `"server"` (по умолчанию клиент) |
| `listen` | **обязателен** — слушатель этого процесса, `"host:port"` |
| `remote` | **обязателен** — клиент: сервер плагина; сервер: цель форвардинга (алиас `"forward"`) |

Остальные ключи — те же опции `plugin_opts` с той же валидацией:

| ключ | тип | смысл | по умолчанию |
|---|---|---|---|
| `password` | строка | **обязательный** секрет; один пароль — любое число клиентов | — |
| `sni` | строка | fake-TLS SNI (пустая строка = не отправлять) | `www.cloudflare.com` |
| `serverkey` | строка | клиент: пин публичного ключа сервера (64 hex) | TOFU |
| `key` | строка | сервер: приватный ключ идентичности (64 hex) | эфемерный (в логе) |
| `ping` | число | интервал keepalive, секунды (0 = выкл) | `2` |
| `timeout` | число | таймаут подключения/хендшейка, секунды | `10` |

Полные комментированные примеры со всеми опциями (включая SNI):
[`examples/standalone-client.json`](examples/standalone-client.json),
[`examples/standalone-server.json`](examples/standalone-server.json).

## IPv4 и IPv6

Каждый адрес в каждом конфиге принимает оба семейства:

* **standalone JSON** — IPv4 `"203.0.113.10:8443"` или IPv6 **в скобках**
  `"[2001:db8::10]:8443"` (`listen` может быть `"[::]:8443"` — все
  интерфейсы; *голый* IPv6-литерал без скобок отклоняется с подсказкой — он
  неоднозначен с разделителем порта);
* **окружение SIP003** — `SS_LOCAL_HOST`/`SS_REMOTE_HOST` принимают IPv4,
  IPv6 в скобках (`[2001:db8::10]`) и голый IPv6 (`2001:db8::10`);
* хостнеймы резолвятся системным резолвером (A + AAAA).

Сам туннель семейно-агностичен от начала до конца (протестирован по IPv6
loopback).

## Версия

`qeli-ss-plugin --version` печатает версию плагина. По умолчанию: `0.1`.
Сборки релизов переопределяют её на тег релиза переменной окружения
`QELI_SS_PLUGIN_VERSION` при сборке:

```sh
QELI_SS_PLUGIN_VERSION=v1.2.3 cargo build --release
```

## Сборка

```sh
cargo build --release          # нативная
cargo test                     # 67 тестов: юнит + end-to-end по реальному TCP

# Linux-бинари с любого хоста (через cargo-zigbuild): СТАТИЧЕСКИЕ musl-сборки —
# без libc-интерпретатора, работают на любом дистрибутиве/Embedded-системе
# (OpenWrt, Entware, роутеры, Alpine) независимо от хостевого libc:
cargo zigbuild --release --target x86_64-unknown-linux-musl
cargo zigbuild --release --target aarch64-unknown-linux-musl
```

Ядро `qeli` подтягивается git-зависимостью с запиненной ревизией; в
`Cargo.toml` есть сниппет `[patch]` для разработки с локальным чекаутом.

## Заметки о тестах

Интеграционный набор гоняет весь стек (mux + хендшейк + носитель +
клиент/сервер) по реальным TCP-сокетам с echo-заглушкой вместо `ss-server`,
включая сценарии враждебного middlebox (порча записей, повторённые записи,
убитые дозвоны, зависший сервер, застрявшие потребители).

> Примечание: на машинах с перехватывающим веб-фильтром (например, локальный
> прокси Kaspersky) тестовые дозвоны по loopback могут прозрачно получать
> HTTP-ошибку вместо ответа. Тесты ретраят такие перехваты; для полностью
> чистых прогонов добавьте тестовые бинарники в исключения антивируса.

## Структура

```text
src/mux.rs        фрейминг мультиплексора (OPEN/DATA/CLOSE/PING/PONG)
src/handshake.rs  fake-tls + auth хендшейк (клиент и сервер, с таймаутами)
src/carrier.rs    долгоживущий туннель: writer/reader, реестр, keepalive,
                  per-stream насос, half-close (WriteFin)
src/client.rs     SIP003-клиент: слушает ss-local, мультиплексирует, ленивый redial
src/server.rs     SIP003-сервер: принимает туннели, демультиплексирует на ss-server
src/opts.rs       SIP003 env + разбор plugin_opts
src/main.rs       CLI (--genkey, --server, --client)
tests/            юнит- и интеграционные тесты
```
