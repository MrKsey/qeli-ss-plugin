# qeli-ss-plugin

SIP003-плагин для [shadowsocks](https://shadowsocks.org): весь TCP-трафик
между `ss-local` и `ss-server` идёт по **одному долгоживущему соединению** —
туннелю [qeli](https://github.com/litvinovtd/qeli) с мультиплексированием
потоков:

```text
приложения → ss-local → [клиент плагина] ══ qeli fake-TLS туннель ══ [сервер плагина] → ss-server → интернет
                              один поток на соединение                        демультиплексирование
```

Для пассивного наблюдателя (DPI) туннель выглядит как обычный трафик TLS 1.3
к хосту CDN. Под этой оболочкой — гибридный постквантовый обмен ключами и
шифрование с аутентификацией.

**English version: [README.md](README.md).**

## Ключевые особенности

* **Выглядит как обычный HTTPS** — по проводу идёт подлинная
  последовательность записей TLS 1.3 с настраиваемым SNI; после рукопожатия
  всё неотличимо от TLS-трафика.
* **Постквантовое рукопожатие** — комбинация X25519 + ML-KEM-768 (FIPS 203):
  туннель остаётся конфиденциальным даже перед будущим квантовым
  противником, способным взломать ECDH (сценарий «перехватить сейчас,
  расшифровать потом»).
* **Одно соединение — много потоков** — каждое соединение shadowsocks
  получает свой поток внутри единого общего туннеля; рукопожатие на каждое
  соединение не нужно.
* **Устойчив к плохим сетям** — испорченные и повторные записи отбрасываются,
  не убивая туннель; смерть удалённой стороны обнаруживается за секунды
  (`ping` + 2 с, по умолчанию ≈ 4 с), клиент автоматически перезапускает
  соединение.
* **Один общий пароль** — один пароль обслуживает любое число клиентов с
  любых хостов; дополнительное закрепление ключа сервера защищает от MITM.
* **Работает везде** — статические musl-бинари Linux (amd64, arm64) идут на
  любом дистрибутиве и встраиваемой системе (OpenWrt, Entware на Keenetic,
  роутеры, Alpine); сборка для Windows amd64 тоже прилагается.

## Как это работает

Плагин сам шифрует всё, что уходит в сеть. Открытыми остаются только два
локальных участка (по определению SIP003 они находятся на loopback):

```text
приложение ─(открыто, loopback)─ ss-local ─(открыто, loopback)─ клиент плагина
                                                                     ║
        всё дальше по проводу — qeli fake-TLS туннель                 ║
        ║  рукопожатие: X25519 + ML-KEM-768                           ║
        ║  записи:      ChaCha20-Poly1305 AEAD + защита от повторов   ║
        ║  содержимое:  кадры мультиплексора внутри записей           ║
                                                                     ║
                                                        сервер плагина ─(открыто, loopback)─ ss-server → интернет
```

* **Рукопожатие** (`src/handshake.rs`) — правдоподобная последовательность
  записей TLS 1.3 (ClientHello → ServerHello → … → Finished) выполняет
  гибридный обмен ключами; пароль проверяется уже *внутри* установленного
  шифрованного канала (сравнение за константное время), поэтому в сеть он
  не попадает никогда.
* **Данные** (`src/carrier.rs`) — каждый кадр мультиплексора запечатывается
  в AEAD-запись (ChaCha20-Poly1305, оформленная под TLS, скользящее окно
  защиты от повторов ≈ 2048 пакетов) ещё до сокета. Собственное шифрование
  shadowsocks продолжает работать поверх, так что транзитный участок
  зашифрован дважды.
* **Мультиплексирование** (`src/mux.rs`) — кадры `OPEN/DATA/CLOSE/PING/PONG`
  (`type(1) ‖ stream(4) ‖ len(2) ‖ payload`, до 16 КиБ на DATA), по одному
  кадру на AEAD-запись. FIN от `ss-local` уходит кадром `CLOSE` и
  превращается в FIN на стороне назначения — настоящее полузакрытие
  соединения, а не разрыв.

### SNI

Задаётся опцией `sni=` (на стороне клиента — SNI находится в ClientHello,
который отправляет клиент):

```sh
--plugin-opts "password=...;serverkey=...;sni=cdn.example.com"
```

По умолчанию: `www.cloudflare.com`. Пустое значение убирает расширение SNI
совсем (это тоже корректный TLS). Значение — ASCII-имя хоста длиной до 253
байт.

### Устойчивость (каждый пункт покрыт тестами)

| Что случается | Что происходит |
|---|---|
| Несколько испорченных или повторных записей | Отбрасываются; туннель умирает только после 8 *подряд* плохих записей |
| Удалённая сторона молча зависла (FIN нет) | Keepalive обнаруживает это за `ping` + 2 с (по умолчанию ≈ 4 с); клиент перезапускает соединение |
| Сторона подключилась и зависла в рукопожатии | Обе стороны завершают по таймауту (`timeout=`, по умолчанию 10 с) |
| Потребитель одного потока перестал читать | Поток отбрасывается через 5 с — остальной туннель продолжает работать |
| Запись зависла | Запись в сеть убивает туннель через 10 с; локальная запись отбрасывает только свой поток через 30 с |

Или сборка из исходников:

```sh
cargo build --release
cargo test                      # 67 тестов: модульные + сквозные по реальному TCP

# статические Linux-бинари с любого хоста (через cargo-zigbuild):
cargo zigbuild --release --target x86_64-unknown-linux-musl

```

Ядро `qeli` подключается git-зависимостью с зафиксированной ревизией; в
`Cargo.toml` есть фрагмент `[patch]` для разработки с локальной копией.

## Использование

### 1. Сгенерировать ключ сервера (один раз)

```sh
qeli-ss-plugin -genkey
# private key (key=...):        9f2c...   ← на сервер, хранить в секрете
# public  key (serverkey=...):  a41b...   ← на клиент, закрепить
```

### 2. Сервер

`ss-server` слушает на loopback; плагин слушает на внешнем интерфейсе и
направляет туда демультиплексированные потоки:

```sh
ss-server -s 127.0.0.1 -p 1310 -k mypassword -m chacha20-ietf-poly1305 &

SS_LOCAL_HOST=127.0.0.1 SS_LOCAL_PORT=1310 \
SS_REMOTE_HOST=0.0.0.0 SS_REMOTE_PORT=8443 \
qeli-ss-plugin -s "key=<hex-приватного-ключа>;password=<пароль-плагина>"
```

### 3. Клиент

```sh
ss-local -s <сервер> -p 8443 -b 127.0.0.1 -l 1080 \
  -k mypassword -m chacha20-ietf-poly1305 \
  --plugin qeli-ss-plugin \
  --plugin-opts "password=<пароль-плагина>;serverkey=<hex-публичного-ключа>"
```

`ss-local` передаёт плагину адреса через переменные окружения `SS_*`;
настройки плагина берутся из `plugin_opts`. Готовые конфигурации для
shadowsocks-libev (CLI) и shadowsocks-rust (JSON) лежат в
[`examples/`](examples/).

### Справочник `plugin_opts`

| опция | сторона | смысл | по умолчанию |
|---|---|---|---|
| `s=1` / `server=1` | обе | роль сервера (`0` = клиент) | клиент |
| `password=<секрет>` | обе | **обязательна**; один пароль — любое число клиентов | — |
| `sni=<хост>` | клиент | fake-TLS SNI (пусто = не отправлять) | `www.cloudflare.com` |
| `serverkey=<hex64>` | клиент | закрепить публичный ключ сервера (анти-MITM) | TOFU |
| `key=<hex64>` | сервер | приватный ключ идентичности (`-genkey`) | эфемерный (печатается в лог) |
| `ping=<сек>` | обе | интервал keepalive; обнаружение смерти ≤ `ping`+2 с | `2` (`0` = выкл) |
| `timeout=<сек>` | обе | таймаут подключения и рукопожатия | `10` |

В значениях действует SIP003-экранирование: `\;`, `\=`, `\\`.

## Автономный режим (без shadowsocks)

Плагин умеет работать и напрямую, по собственному **JSON**-конфигу — без
`ss-local`/`ss-server` и без переменных окружения `SS_*`. Автономный клиент —
простой TCP-форвардер (каждое принятое соединение = один поток в общем
туннеле); автономный сервер направляет потоки на **любой** TCP-сервис
(HTTP-сервер, sshd, база данных — или на ss-server, если он всё-таки нужен
в середине):

```sh
qeli-ss-plugin -c standalone-server.json   # на сервере
qeli-ss-plugin -c standalone-client.json   # на клиенте
```

Ключи конфига: `role` (`"client"`/`"server"`), `listen` и `remote`
(обязательны; `forward` — синоним `remote`), плюс все опции `plugin_opts`
из таблицы выше (`password`, `sni`, `serverkey`, `key`, `ping`, `timeout`).
Поле `"_comment"` разрешено и игнорируется; неизвестный ключ — **ошибка**
конфигурации: опечатка не должна проходить молча.

Полные примеры с комментариями:
[`examples/standalone-client.json`](examples/standalone-client.json),
[`examples/standalone-server.json`](examples/standalone-server.json).

## IPv4 и IPv6

Любой адрес в любом конфиге принимает оба семейства:

* **автономный JSON** — IPv4 `"203.0.113.10:8443"` или IPv6 в скобках
  `"[2001:db8::10]:8443"`; `listen` может быть `"[::]:8443"` (все
  интерфейсы). «Голый» IPv6-литерал без скобок отклоняется с подсказкой —
  он неотличим от разделителя порта;
* **окружение SIP003** — `SS_LOCAL_HOST`/`SS_REMOTE_HOST` принимают IPv4,
  IPv6 в скобках и без скобок;
* имена хостов резолвятся системным резолвером (A + AAAA).

## Версия

```sh
qeli-ss-plugin -v        # печатает версию, например v1.0.2
```

В релизных сборках версия берётся из тега релиза (переменная
`QELI_SS_PLUGIN_VERSION` при сборке); локальная сборка по умолчанию
печатает `0.1`.

## Ключи командной строки

```
-c <file>   путь к JSON-конфигу (автономный режим)
-client      роль клиента (по умолчанию)
-s           роль сервера
-genkey      сгенерировать пару ключей сервера и выйти
-v           напечатать версию и выйти
-h           напечатать справку и выйти
```

## Тесты

```sh
cargo test
```

Интеграционный набор прогоняет весь стек (мультиплексор + рукопожатие +
носитель + клиент/сервер) по реальным TCP-сокетам с echo-заглушкой вместо
`ss-server`, включая сценарии враждебного посредника: порча записей,
повторные записи, обрыв дозвона, зависший сервер, застрявшие потребители,
IPv6 loopback.

> Примечание: на машинах с перехватывающим веб-фильтром (например, локальным
> прокси антивируса) тестовые подключения по loopback могут незаметно
> получать HTTP-ошибку вместо ответа. Тесты повторяют такие попытки; для
> полностью чистых прогонов добавьте тестовые бинари в исключения
> антивируса.

## Структура

```text
src/mux.rs        кадры мультиплексора (OPEN/DATA/CLOSE/PING/PONG)
src/handshake.rs  рукопожатие fake-TLS + проверка пароля (клиент и сервер, с таймаутами)
src/carrier.rs    долгоживущий туннель: чтение/запись, реестр потоков,
                  keepalive, мостик к локальным сокетам, полузакрытие
src/client.rs     сторона клиента: слушает ss-local, мультиплексирует, перезапуск соединения
src/server.rs     сторона сервера: принимает туннели, демультиплексирует на адресат
src/opts.rs       окружение SIP003, разбор plugin_opts и JSON-конфига
src/main.rs       командный интерфейс
tests/            модульные и интеграционные тесты
```
